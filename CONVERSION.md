# Путь клиента в Demo2

Существующий сайт Demo1 сохранён и расширен в Demo2. Главная, три SEO-страницы,
стили, анимации, инструкции, тарифы и PWA остаются. Цель изменений — дать два
понятных маршрута без обязательного чтения всех разделов.

## Что реализовано

1. **«3 дня бесплатно»** на первом экране ведёт непосредственно на существующую
   страницу входа/регистрации кабинета. Выбор платного тарифа перед этим не нужен.
2. **«Выбрать тариф»** прокручивает главную сразу к четырём платным карточкам
   (`#paid-plans`). На внутренних страницах ведёт к тому же блоку главной.
   Закреплённая шапка не закрывает начало блока.
3. В общем блоке цен (`#tariffs`) над платными тарифами размещена широкая карточка
   **«3 дня бесплатно»**: 0 ₽ за пробный период, 3 ГБ, одно устройство, без карты.
   «Начать бесплатно» ведёт в тот же кабинет. Из пояснения под платными тарифами
   можно вернуться к бесплатной карточке (`#trial-access`).
4. Платные кнопки содержат срок и полную стоимость: 30 дней за 149 ₽, 90 за 399 ₽,
   180 за 699 ₽, 365 за 1 199 ₽. Первоначальные цены и описания не изменены.
5. Нижний CTA и первые экраны внутренних страниц также предлагают два маршрута.
   Контекстные ссылки «Как это работает», настройка устройства и схема сохранены
   отдельными текстовыми ссылками.

Все переходы — обычные HTML-ссылки. JavaScript, диалоги и дополнительный шаг выбора
на сайте для входа в кабинет не требуются. Активация, регистрация, оплата и выдача
подписки происходят в существующем кабинете, а подключение — через Happ.

## Граница интеграции кабинета

Проверка публичных `/login` и `/buy/get` из cloud-среды получила отказ прокси
`403 Forbidden`. Реальная активация пробного доступа, условия оплаты и возможность
передачи выбранного тарифа через вход не проверены. Код кабинета отсутствует в
этом репозитории. Никакие оплаты, регистрации и действия с аккаунтом не выполнялись.

Сохранены известные адреса, без выдуманных параметров:

- `trial_url`: `https://lk.flowpass.online/login`;
- `checkout_urls`: для каждого из четырёх сроков пока
  `https://lk.flowpass.online/buy/get`.

Настройки находятся в `_source/site.json` и подставляются сборкой в ссылки. Когда
владелец кабинета подтвердит реальные публичные ссылки на конкретные тарифы,
нужно заменить значения для `30`, `90`, `180`, `365` и пересобрать сайт. Ссылки
с паролями/логинами в URL не допускаются; секретные ссылки автоматического входа
не должны публиковаться в настройках или HTML.

**Пока все платные кнопки открывают общий экран оформления. Выбранный срок на
стороне кабинета автоматически не устанавливается этой доработкой.** Сохранение
тарифа после регистрации/входа и автоматическая активация триала требуют
подтверждённого контракта/доработки самого кабинета. Статический сайт не выдаёт
переход по кнопке за оплату или активацию.

## Проверки и публикация

```bash
python3 tools/build.py
python3 tools/check-site.py
node tools/check-browser.cjs
node tools/check-pwa.cjs

python3 tools/build.py --target production --out /tmp/flowpass-release
python3 tools/check-site.py --root /tmp/flowpass-release --base / --target production
SITE_ROOT=/tmp/flowpass-release SITE_BASE=/ node tools/check-browser.cjs
```

Проверяются: направления CTA, прокрутка к платным тарифам, отсутствие перекрытия
шапкой, бесплатная карточка над платной сеткой, четыре цены и ссылки, адаптивность,
работа без JS и исходные интерактивные функции. PWA-тест проверяет офлайн-копию
и обновление версии. Тесты не совершают платежей и не доказывают работу кабинета.

Push Demo2 не переключает настройки GitHub Pages. Если источником публикации
остаётся Demo1, для просмотра Demo2 нужно выбрать её в Settings → Pages → Branch
и корень `/`, сохранив нужную конфигурацию публикации. На том же URL используется
та же PWA: после успешного deploy установленное приложение предложит обновление.

Реальные показатели конверсии не измерялись; рост продаж не заявляется. Дальнейшие
замеры должны различать клики CTA, регистрации, активации и подтверждённые оплаты.
