# Flowpass: SEO, ветка Demo1

Реализация первой волны по `Flowpass_SEO_Development_Brief.txt` от 06.11.2026.
База — `main`, коммит `70e4165`. Сайт расширен поверх актуального лендинга;
вторая волна и публикация на коммерческом домене в эту работу не входят.

## Что реализовано

- Отдельные статические документы `/vpn/iphone/`, `/vpn/android/`, `/smart-routing/`:
  разные поисковые намерения, Title, Description, H1, инструкции, ограничения,
  FAQ, CTA, ссылки на соседние страницы и BreadcrumbList.
- Полные инструкции доступны в исходном HTML без JavaScript. Схема маршрутов
  переиспользована с главной, рядом есть постоянная текстовая альтернатива.
- Общие header/footer, CSS/JS. Исходные стили и скрипты вынесены без изменения;
  новая навигация и стили статей добавлены отдельно. Сохранены четыре тарифа,
  переключение пяти платформ, FAQ, reveal, интерактивная схема, пульсация и
  переливание рамки годового тарифа, reduced motion.
- На главной сохранены исходные Title, H1, Description, все прежние секции и
  внешние ссылки. Добавлены статические ссылки на инструкции, раздел материалов,
  ссылка на объяснение маршрутизации и ссылки в подвале. Предложенные в ТЗ новые
  формулировки главной не утверждены и не применены.
- Canonical, Open Graph, robots meta, русская локаль, реальное изображение главной
  для соцсетей (1200×630), собственная страница 404. Canonical и og:url каждой
  страницы указывают на её будущий коммерческий URL; на главной сохранена
  первоначальная канонизация на `https://flowpass.online/`.
- SoftwareApplication заменён на Service с существующим предложением 149 RUB за
  30 дней. Flowpass описан как услуга, Happ — как сторонний клиент. Выдуманных
  рейтингов, отзывов, реквизитов оператора и обещаний rich results не добавлено.

## Источники и сборка

Зависимости сборки — только Python 3, стандартная библиотека. В корне и папках
URL закоммичены готовые документы: Node.js на хостинге не нужен.

- `_source/home.html.in` — сохранённая полная главная с общими компонентами.
- `_source/header.html.in`, `footer.html.in`, `diagram.html.in` — общие компоненты.
- `_source/pages/` — отдельные содержательные статьи, не шаблонные дубликаты.
- `_source/site.json` — настройки окружения; без ключей и секретов.
- `assets/site.css`, `assets/site.js` — исходное оформление и интерактивность.
- `assets/seo.css` — оформление новых материалов и расширенной навигации.
- `assets/flowpass-social.png` — снимок реального первого экрана сайта, не скриншот
  приложения Happ. Снимки приложения не предоставлены и не подменялись выдуманными.

Редактировать нужно исходники и общие assets, после чего пересобирать документы.
Не править сгенерированные страницы независимо от шаблонов.

```bash
# Демоверсия GitHub Pages, все внутренние пути с /vlad/:
python3 tools/build.py
python3 tools/check-site.py

# Изолированная сборка для будущего коммерческого релиза:
python3 tools/build.py --target production --out /tmp/flowpass-release
python3 tools/check-site.py --root /tmp/flowpass-release --base / --target production

# Браузерная проверка в подготовленной cloud-среде (Playwright + Chromium):
node tools/check-browser.cjs

# Та же браузерная проверка release-сборки без префикса /vlad/:
SITE_ROOT=/tmp/flowpass-release SITE_BASE=/ node tools/check-browser.cjs
```

`--base-url /другой-префикс/` переопределяет префикс ссылок и assets. По умолчанию
demo использует `/vlad/`, production — `/`. Скрипт не меняет настройки GitHub Pages
или DNS и не выполняет публикацию. На GitHub Pages исходники с `_` исключаются
обычной Jekyll-сборкой. На коммерческий сервер выгружать только release-папку,
которая не содержит исходников и инструментов.

Проверка браузера поднимает временный локальный сервер, проходит страницы и
закрывает его. `CHROMIUM_PATH` позволяет указать установленный Chromium.
`UPDATE_SOCIAL_IMAGE=1 node tools/check-browser.cjs` пересоздаёт изображение
главной; использовать только после намеренного изменения первого экрана.

## Индексация demo и production

Вопрос о `noindex` для демо задан отдельно, как требует раздел 8 ТЗ.
Пока согласование не получено, сохранена допустимая индексация (`index, follow`),
а исходный коммерческий canonical не изменён. **Canonical не запрещает индексацию.**

После явного согласования установить `demo_noindex: true` в `_source/site.json`
и выполнить `python3 tools/build.py`. Тогда все четыре страницы демо получат
`noindex, follow`; SEO-контент и JSON-LD останутся. Production всегда получает
`index, follow` независимо от переключателя демо. Исключение демо из поиска
нельзя считать настроенным, пока это изменение не согласовано и не опубликовано.

Production-сборка генерирует `sitemap.xml` с четырьмя коммерческими URL и
`robots.txt` со ссылкой на неё. Demo не публикует sitemap: это не самостоятельная
SEO-площадка, и sitemap другого хоста не должен перечислять коммерческие URL.
Пустая sitemap не генерируется.

Не блокировать страницы демо через `Disallow: /`: робот должен иметь возможность
прочитать `noindex`. Файл `/vlad/robots.txt` на GitHub Pages проекта **не управляет**
всем хостом `ivangusarov386-lab.github.io`: правила для робота действуют в корневом
`/robots.txt` хоста. Поэтому управление демо сделано через HTML meta robots.

## Перед коммерческим релизом

- Согласовать метаданные главной отдельно, если нужно менять брендовый слоган.
- Собрать Wordstat/SERP и данные Вебмастера/Search Console; уточнить карту запросов,
  проверить каннибализацию. Нули вместо неизвестной частотности не подставлять.
- Проверить актуальные 3 дня / 3 ГБ / одно устройство, все четыре тарифа, два
  устройства в платном доступе, ручное продление, способы оплаты и возвратов.
  Новые страницы используют условия текущего лендинга, а не заново подтверждённые
  данные личного кабинета. При изменении условий обновить все упоминания и schema.
- Проверить реальные шаги Happ на iOS/Android и добавить предоставленные реальные
  скриншоты с уникальными alt и заданными размерами. Не выдумывать минимальные
  версии ОС, поддерживаемые TV и точный механизм маршрутизации.
- Подтвердить условия AI-маршрута. Исходная схема сохранена; новая статья прямо
  указывает, что демонстрация не подтверждает доступность любого AI-сервиса.
- Верифицировать операторские сведения, возвраты и обработку данных по настоящим
  документам; публикации недостоверных реквизитов нет.
- Выложить production-сборку на `flowpass.online`, проверить HTTPS, HTTP 200/301/404,
  canonical, отсутствие дублей, robots, sitemap и социальное изображение уже на
  настоящем домене. Настроить отдачу 404 с соответствующим HTTP-статусом.
- Запустить Schema.org validator и Rich Results Test. Измерить Lighthouse/PSI для
  mobile/desktop и отдельно полевые CWV (LCP, INP, CLS). Цели ТЗ не являются замерами.
- Подключить Search Console, Яндекс.Вебмастер и аналитику при наличии доступа и
  согласованных идентификаторов. Считать клики CTA/тарифа отдельно от подтверждённых
  активаций и оплат. Счётчики, учётные записи и доступы не выдумывались.
- После оценки спроса и качества первой волны рассмотреть Windows, macOS, `/pricing/`
  и `/guides/`. Пока таких URL нет; ссылки ведут на реальные якоря главной.

Ветка Demo1 не меняет опубликованный main. Публикация Demo1 в GitHub Pages требует
отдельной настройки источника публикации; push ветки сам по себе её не включает.

Последующие правки Demo1: ссылки на подробные инструкции размещены в третьем шаге
соответствующей платформы; для Windows/macOS/TV ссылки не выдумываются. На светлой
кнопке пробного доступа используется движущийся SVG-блик по контуру, без CSS-маски;
при reduced motion движение отключено. Общие CSS/JS подключаются с хэшем содержимого
в query-параметре, чтобы изменения не скрывались за старым кэшем браузера.
