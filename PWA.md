# Flowpass PWA

Ветка Demo1 поддерживает установку сайта на главный экран и запуск в отдельном
окне приложения. Это приложение сайта с тарифами, инструкциями и переходами
в кабинет. Системное VPN-подключение выполняет Happ; PWA не заменяет VPN-клиент.

## Установка

- **iPhone / iPad:** открыть опубликованный сайт в Safari → «Поделиться» →
  «На экран Домой» → «Добавить». Из встроенного браузера сначала перейти в Safari.
- **Android:** открыть сайт в Chrome → раздел «Установить» на сайте →
  «Установить Flowpass». Если браузер не предлагает системный диалог, использовать
  меню Chrome → «Установить приложение» / «Добавить на главный экран».
- **Компьютер:** Chrome или Edge → значок установки в адресной строке либо меню
  браузера. В приватном режиме установка может быть недоступна.

После установки значок запускает Flowpass в режиме `standalone`, без обычной
адресной строки. На iOS фактическая установка требует действий пользователя;
сайт не может открыть системный диалог установки за него.

## Офлайн и обновления

Первое посещение требует сети. Service worker сохраняет главную, три страницы
инструкций/маршрутизации, офлайн-страницу, локальные стили, скрипты и иконки.
После успешного сохранения эти страницы открываются без сети, даже если конкретная
инструкция ещё не посещалась. Вкладки, меню, FAQ и схема работают локально.

Кабинет, оплата, Telegram, App Store, Happ, Google Fonts и любые другие внешние
ресурсы **не кэшируются**. Для кабинета, активации подписки и VPN нужна сеть.
Шрифты без сети используют системный fallback. Удаление данных сайта или очистка
хранилища системой может удалить офлайн-копию; тогда нужно снова открыть сайт
онлайн и дождаться сохранения.

Онлайн страницы запрашиваются из сети; офлайн выдаётся согласованная сохранённая
версия. Неизвестный адрес онлайн остаётся HTTP 404, без подмены главной; неизвестный
адрес офлайн получает страницу «Нет подключения» с HTTP 503 и ссылками на сохранённые
материалы. Не используется универсальная подмена всех URL одним HTML-документом.

При появлении новой версии показывается «Доступна новая версия Flowpass» →
«Обновить». Приложение активирует новый worker и перезагружает страницу только
после нажатия. При первом сохранении автоматической перезагрузки нет. Новая
версия определяется содержимым HTML, assets и worker, поэтому обычные правки
текста также обновляют офлайн-копию. Старые кэши удаляются только внутри собственного
префикса Flowpass; кэши других приложений на том же хосте не затрагиваются.

## Сборка и публикация

Runtime не требует Node.js, пакетов или серверной части. PWA работает через HTTPS
либо на localhost для разработки. GitHub Pages предоставляет HTTPS. Ветка Demo1
должна быть выбрана источником Pages; успешный push ещё не означает успешное
развёртывание. Дождаться `Success` в workflow Pages перед проверкой на телефоне.

```bash
python3 tools/build.py
python3 tools/check-site.py
node tools/check-pwa.cjs
node tools/check-browser.cjs

python3 tools/build.py --target production --out /tmp/flowpass-release
python3 tools/check-site.py --root /tmp/flowpass-release --base / --target production
SITE_ROOT=/tmp/flowpass-release SITE_BASE=/ node tools/check-pwa.cjs
```

Demo использует `id`, `start_url`, `scope` и worker scope `/vlad/`; production —
`/`. Worker размещается в корне своего scope, `Service-Worker-Allowed` не требуется.
Манифест — `manifest.webmanifest`, worker — `sw.js`; оба генерируются сборкой.
`assets/pwa.js` определяет базовый путь по собственному URL. Обе конфигурации
тестируются отдельно, без запросов к коммерческому кабинету.

Исходники: `_source/sw.js.in`, `_source/install.html.in`, `_source/notices.html.in`,
`assets/pwa.js`, `assets/pwa.css`, `tools/build.py`. PNG-иконки 192/512, maskable 512
и Apple touch icon 180 созданы из существующего favicon. Для намеренной смены
иконок: `node tools/make-icons.cjs` в подготовленной среде с Chromium/Playwright,
затем пересобрать сайт. Готовые PNG хранятся в Git; растеризация при публикации не нужна.

На другом хостинге отдавать `.webmanifest` как `application/manifest+json`, worker
как JavaScript; избегать длительного кэширования `sw.js`/HTML на CDN. Не публиковать
production-сборку под `/vlad/` без соответствующего `--base-url`.

## Проверено локально

- Chromium в обычном профиле: `Page.getAppManifest` и
  `Page.getInstallabilityErrors` не сообщают ошибок.
- Размеры PNG, maskable-иконка, Apple touch icon, области действия demo/production.
- Все четыре страницы без сети, интерактивные вкладки и отдельный offline fallback.
- Отсутствие кэширования внешних ресурсов, корректный 404 онлайн.
- Цикл обновления: ожидание → уведомление → нажатие → новый worker → перезагрузка
  → новая офлайн-версия; чужой тестовый кэш сохранён.
- Обработка install events протестирована с имитацией подтверждения ОС. Это
  проверка обработчиков, а не физическая установка приложения на телефон.
- Регрессии основного сайта: меню, закреплённая шапка, пять вкладок, FAQ, анимации,
  reduced motion, адаптивность и HTML без JavaScript.

Физическая установка на iPhone/Android и поведение системных safe areas должны
быть дополнительно проверены на настоящих устройствах после HTTPS-публикации.
Настоящий Safari/WebKit в текущей среде отсутствует; мобильный viewport Chromium
не считается проверкой Safari. Публичные URL из этой среды могут блокироваться
сетевой политикой; локальный тест не доказывает успешность GitHub Pages deploy.
